# Contributing to OpenBeat

Choose a focused change: review a clinical explanation, improve an accessible interaction, fix event timing, or propose one learning objective.

1. Run the existing app and read its model limitations.
2. Explain the problem with a reproducible example.
3. Keep educational content separate from rendering logic.
4. Cite sources for changes to medical content. Write original explanations; do not copy textbook figures or use patient information.
5. Add meaningful tests for changes to event ordering, waveform timing or supported ranges.
6. Run tests, typecheck, lint and production build. Check desktop, mobile and keyboard behaviour for UI changes.
7. Describe what changed, evidence, verification and remaining review needs.

Do not mark content reviewed without an actual reviewer, date and source revision. See docs/CLINICAL_REVIEW.md.

Code contributions use MIT; original educational text uses CC BY 4.0. Identify any third-party content and its licence. Never commit credentials, patient records or local tooling.

The repository URL will be added after publication. Until then, use the creator profile linked in README for project discovery; do not assume a repository name.
